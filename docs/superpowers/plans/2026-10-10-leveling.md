# Run Leveling Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task. The user approved implementation in this chat; proceed locally.

**Goal:** Add XP and meaningful upgrade choices within each run.

**Architecture:** A scene-owned progression node emits XP and level signals.
The game queues rewards and pauses for a dedicated UI; resource definitions
apply upgrades through a player method. Preserve the existing defeated signal.

**Tech Stack:** Godot 4.7, GDScript, scene and Resource files; no dependencies.

**Spec:** `docs/superpowers/specs/2026-10-10-leveling-design.md`

## Global Constraints

- XP/score are independent; all progression resets with the game scene.
- Thresholds: 50/80/110; skeleton XP: 10.
- Upgrades: damage +5, max/current HP +20, range +15, current speed +10%.
- Three distinct choices per reward; repeated upgrades across levels allowed.
- Maintain the existing combat and navigation behavior.

## Review Focus

- Several deaths during one attack must finish before pausing.
- One large XP grant must yield all its rewards, sequentially.
- Hidden, invalid, or repeated selections must not mutate stats.
- Death before the deferred panel opens must not pause the game.
- Reloading while paused must leave a fresh, playable level 1 run.
